## SPEC §9

- Row (F-NEW): **`MetricsReport` is the one report the CLI, the Panel and the CSV read.** `metrics::metrics_report(&CostInput)` returns `rows` (one per feature and per milestone that has a feature event), `mission` (`MissionSummary`: cycle, fallback count, first pass, rework, waste, fix loops, throttled minutes, stage times per template lane, bottleneck), `throttled`, `ignored_after_handed_to_cd`, and the flattened `CostReport` (`overhead`, tokens, model comparison, budget). `to_csv()` writes the 22-name header of `scripts/contract-checks/metrics-header.txt`.
- Row (F-NEW): **Cycle clock from the template (F-028).** `metrics::cycles` reads the template's `clocks`: start `feature.defined`, else the feature's first `task.started` (counted as `fallback_features`; M0: 6 of 12), end `handed_to_cd`, else the milestone's integration while no PR exists, else open (reads "now"). Events after `handed_to_cd` are counted in `ignored_after_handed_to_cd` and add no time. M0 has no `handed_to_cd`, so every row ends open.
- Row (F-NEW): **Row figures are clipped to the cycle window.** First pass, rework, the eight waste causes and waiting time of a feature row count only the intervals inside that feature's cycle window, so `first_pass_active_s + rework_s + waste (excluding the rework cause) + 60 × throttled_minutes ≤ cycle_s` per feature row (±1 s of rounding; `throttled_minutes` rounds up to a minute, so M0's `s-*` rows read up to 8 s over). Milestone rows add their features, so they exceed the milestone's own cycle when features overlap in time (parallel work).
- Row (F-NEW): **Milestone rows exist only for milestones with a feature event** (M0 golden: `m0` and `s`, 14 rows with the 12 feature rows).
- Row (F-NEW): **`bottleneck` and `stage_s` iterate `template.lanes`.** The bottleneck is the lane with the most stage seconds (M0: `scrutiny`); no lane name is a constant (F-041).
- Row (F-NEW): **Overhead apportionment.** `[metrics].overhead_apportionment = separate` (default): the `overhead` line (label `separate`) holds the events with no feature (orchestrator time, compaction recovery, the 13 questions and 12 `intent.answered` of M0), is in no feature row and not exported. `equal`: the same seconds and the same cost are split equally across the mission's features and the label is `apportioned`; the sum is identical in both.
- Row (F-NEW): **The oracle is a tolerance diff.** `metrics::compare_csv(reference, produced, &Tolerance)` keys rows by (`scope`, `id`); each duration column ±1 s, each token column ±1, `cost_usd` ±0.01, `rework_windows` equal, `throttled_minutes` ±1, `price_table` equal; a missing or extra row on either side is a deviation; a header that is not the contract is an `OracleError::Header`. `observatory-cli metrics <capture> --diff <reference.csv>` prints rows compared, deviations, one line per deviation and the maximum deviation per column; exit 1 on a deviation.
- Row (F-NEW): **`observatory-cli metrics <capture> --csv | --json | --diff <file>`**; `--csv` conflicts with `--json` and `--diff`. The report is made at the capture's last non-Panel event, so one capture gives one answer on any day.
- Row (F-NEW): **`Notes::from_store`** (store feature only, wasm stays clean) reads the check names of gate windows (`gate_window_checks`) and the answers of `human_actions.payload_ptr`; the CLI over a capture uses `Notes::default()`; `pauseReason` is not in the store, so a host supplies it with `Notes::with_pause_reason` and the reason reads `unknown` otherwise.
