# m5-telemetry-exporter-and-status

## SPEC §9

- Row (F-NEW): **Telemetry exporter to the local collector, status surface and header rule** (feature `m5-telemetry-exporter-and-status`, batch 2, D-046; rule 24, no scope, cap or model change). `core::telemetry` gains `resolve_start(cfg, lookup)` (off `(config)`, off `, no keychain item <name>`, exporting; the keychain closure runs only for a non-empty `headers_keychain_item` and only after `start_check` accepted the plan), `parse_header` (first `=`), `OtlpHeader` (value redacted under `Debug`), `TelemetryReport {enabled, reason, state, endpoint}` (the `telemetry_status` payload; `{enabled, reason}` kept flattened) and `mission_sample` (the eleven instruments for one mission, labels bounded). The config keys follow D-046: `[telemetry].endpoint` default `http://localhost:4318`, `headers_keychain_item` default empty (replaces `keychain_service`). The exporter is `src-tauri/src/telemetry.rs`: `opentelemetry`/`opentelemetry_sdk`/`opentelemetry-otlp` 0.33.1 (`http-proto`, `metrics`, no default features), a ureq `HttpClient` that logs `telemetry.post{method, url, status}` and sends only content-type, content-encoding, user-agent and the configured header (so `OTEL_EXPORTER_OTLP_HEADERS` is dropped even though the SDK reads it), resource `service.name` and `service.version` only (`Resource::builder_empty`), no unit, `PeriodicReader` every `metric_export_interval_s`. The `telemetry{state, endpoint}` line is logged at start, `telemetry_status` serves it, the UI status bar reads `telemetry: <state>`. The app log drops fields named `authorization`, `token`, `header`, `secret`.
- Row (F-NEW): **Sampling points.** A mission is folded into the instruments when it is opened (`open_replay`, `open_mission`, `attach`) and, at most once per export interval, after a live `events_appended` batch (ingest thread, own store connection). Counters are running totals diffed against the last sample (never negative); a histogram observation is recorded once (`mission.cycle_seconds` when the mission holds `handed_to_cd`, `feature.cycle_seconds` per completed feature). The `milestone` label of work no milestone owns is `none` and takes one of the seven named slots.

## Decisions

- None new. `docs/decisions/D-047-telemetry-series-allocation.md` (from `m5-telemetry-series-plan-core`) already fixes the allocation; D-046 is applied, not amended.

- B-new: a live mission's last batch inside an export interval is folded in at the next batch, not on its own; `Telemetry::stop` does not sample. A timer-driven sample would close it.
- B-new: `deny_unknown_fields` on `[telemetry]` means a user config that still carries `keychain_service` fails to load. Only the example config carried it.
- B-new: `mission_switch_min_interval_min` is enforced in the exporter only (a second mission is ignored for 30 minutes after the first was recorded); no UI text says a mission was skipped.
- B-new: app traces (`/v1/traces`, architecture §10 last sentence) are not exported: the slice's scope is metrics, VAL-TELEM-005..009 name no trace check.
