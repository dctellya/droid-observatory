## SPEC §9

- Row (F-NEW): **Export is one function in core.** `metrics::export` (`ExportFormat {Csv, Json}`, `ExportFile {format, file_name, mime, text, rows}`, `report_at_last_event`, `MetricsReport::export`) builds the text the CLI prints (`observatory-cli metrics --csv|--json` now calls the same functions). File name `<mission>-metrics.<ext>`. The browser host builds the report in wasm and downloads a Blob; the window calls the `export` command, which writes the same text to a path (`~/` expanded, folders created). Nothing is recomputed by the UI.
- Row (F-NEW): **The Panel, the Cost tab and the library read the CSV rows.** `PanelMetrics.milestones` (`MilestoneFigures`: cycle, first-pass active, rework, rework windows, throttled minutes, tokens, cost) and `CostTab` (`cycle_s`, `rework_windows`, waste) take their figures from the milestone's `MetricsReport` row. The Panel's waste bars stack the report's rows. The library `Headline` is defined from the same rows: `cycle_s` is the engineering clock (`report.mission.cycle.seconds`, F-028), `waste_s` the CSV feature-waste sum, `cost` the sum of the milestone rows; the mission overhead (`overhead_tokens`, `overhead_cost`, `#[serde(default)]`) is shown apart as `library-overhead`. On M0: 56919 s, 101360 s, 9.40 USD (2026-10-22) plus 71.08 overhead (was first-to-last event 83027 s, waste 129978 s, cost 80.47 from the pre-CSV definitions).
- Row (F-NEW): **The window reads the configured price table through the shell.** Commands `metrics {mission_id}` (report with `[metrics].price_table`, bundled table when the file is missing), `price_table` (its text, parsed in wasm by Board and Details) and `export_default_path`; the browser keeps the bundled `2026-10-22` table.
