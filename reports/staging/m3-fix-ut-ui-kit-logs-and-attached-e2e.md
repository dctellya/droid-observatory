## Library

- Attached e2e recipe (VAL-CTRL-013): the suite's app config points `[ingest].factory_sessions_dir` at
  `RUN_DIR/sessions` (`lib/env.ts`). `lib/attach.ts` `seedAttachedSession()` rewrites the S root session
  (`fixtures/streams/2026-10-22-observatory-v1-s.jsonl` and its `.settings.json`) with a fresh session id and writes
  both to `RUN_DIR/sessions/-home-user-e2e-attach/<id>.{jsonl,settings.json}`; a new id keeps its event ids apart
  from the panel spec's replay of the same fixture. The running watcher discovers the new file within one poll
  (`jsonl_poll_ms`); `[aria-label="watched-session"]` lists it and its `attach-session` button opens the board, which
  renders `ControlBar::attached` (`control-message-text`, `control-message`, `terminal-instruction`,
  `terminal-text`). Evidence read after the click: `sqlite3 -readonly RUN_DIR/observatory.sqlite` for
  `human_actions` (`message|sent`) and the `source = 'app'` event (`app|human|plan|human`); the app log is the newest
  `reports/e2e/<date>/wdio-*.log`, where `human_action ... action=Message { text_len: N }` appears and the count of
  `host_control` lines does not move.
- Theme PNGs: the `afterTest` hook names a PNG after the case title, so a case that presses `theme-dark` /
  `theme-light` and checks `document.documentElement.dataset.theme` is what produces a dark or light screenshot.
- `reports/e2e/<E2E_DATE>/` for this feature's run: `2026-10-25-fix` (git-ignored; the run is pasted in the handoff).
